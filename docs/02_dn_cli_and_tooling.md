# 02. `dn` CLI Tooling & Engine Lifecycle

## 1. CLI Execution Flow & Structure

The primary tool for interacting with DartNative is the `dn` CLI executable located at `~/zero/bin/dn`.

### Invocation Pipeline

```
  `dn` command executed in shell
              │
              ▼
    ~/zero/bin/dn (Bash wrapper script)
              │
              ▼
    ~/zero/bin/internal/shared.sh
              │
              ▼
  Checks cache / updates Dart SDK snapshot
              │
              ▼
  Executes `packages/flutter_tools` executable snapshot via Dart VM
```

1. **`bin/dn` Wrapper**: Initializes `FLUTTER_STORAGE_BASE_URL` (defaulting to `https://cdn.dartnative.com`) and resolves symlinks.
2. **`bin/internal/shared.sh`**: Checks if the tool snapshot (`flutter_tools.snapshot`) matches the source code inside `packages/flutter_tools/`. If outdated or missing, it re-compiles the tool snapshot using the embedded Dart SDK.
3. **`packages/flutter_tools`**: Contains the command handlers (`ConfigCommand`, `CreateCommand`, `RunCommand`, `BuildApkCommand`, `BuildIosCommand`, `CodePushCommand`, `PluginSyncCommand`).

## 2. SDK Layout & Engine Cache Management

When unpacked via `install.sh`, the SDK resides at `~/zero` (or `$DN_INSTALL_DIR`).

```
~/zero/
├── bin/
│   ├── dn                      # Primary CLI entrypoint
│   ├── dart                    # Embedded Dart binary wrapper
│   ├── flutter                 # Alias wrapper for backwards compatibility
│   ├── internal/
│   │   ├── engine.version      # Git SHA pin for platform engine binaries
│   │   ├── shared.sh           # Core environment initialization
│   │   └── dn_sdk.source       # Release source commit hash
│   └── cache/                  # Downloaded engine binaries (~315MB - 600MB)
│       ├── artifacts/          # iOS Frameworks / Android AARs & NDK tools
│       └── dart-sdk/           # Embedded Dart SDK toolchain
└── packages/
    ├── flutter/                # DartNative framework Dart package
    └── flutter_tools/          # CLI source code compiled into tool snapshot
```

### Engine Pinning & Cache Retention
- **Engine Pin**: The file `bin/internal/engine.version` holds the exact commit hash of the compiled C++ engine artifacts hosted on `cdn.dartnative.com`.
- **Cache Persistence**: Running `install.sh` to update the SDK automatically preserves `bin/cache/` to avoid re-downloading large engine artifacts (~315MB for iOS, ~280MB for Android).

## 3. Automatic Plugin Registration

DartNative plugins do not use legacy `MethodChannel`Registrars. Instead, plugins rely on static native registrations generated at build time.

When running `dn pub get` or `dn run`, the CLI scans `pubspec.lock` for packages declaring a `dartnative` plugin entry point. It automatically generates `lib/dartnative_plugin_registrant.dart` in your project:

```dart
// Auto-generated by `dn pub get`. Do not edit manually.
import 'package:dartnative_sqlite/dartnative_sqlite.dart';
import 'package:dartnative_video_player/dartnative_video_player.dart';

class DartNativePluginRegistrant {
  static void registerAll() {
    SqlitePlugin.registerWith();
    VideoPlayerPlugin.registerWith();
  }
}
```

In `main.dart`, `DartNativePluginRegistrant.registerAll()` must be invoked as the first line of execution.

## 4. Code Push Architecture (`dn release` & `dn patch`)

DartNative includes an integrated Code Push mechanism for instant over-the-air (OTA) Dart code updates without app store re-submission.

### Code Push Mechanics

```
┌────────────────────────┐      dn release      ┌────────────────────────┐
│  AOT Kernel / Binary   │────────────────────> │  .dn_code_push/        │
│  Release Version v1.0  │                      │  release_v1.0.kernel   │
└────────────────────────┘                      └────────────────────────┘
            │                                               │
            │ Bugfix Applied                                │ Diff / Patch
            ▼                                               ▼
┌────────────────────────┐      dn patch        ┌────────────────────────┐
│  Updated Dart Kernel   │────────────────────> │  OTA Patch Bundle      │
│  Release Version v1.0  │                      │  (Uploaded to Registry)│
└────────────────────────┘                      └────────────────────────┘
```

1. **`dn release [android|ios]`**:
   - Compiles the application and generates `.dn_code_push/release_<version>.kernel`.
   - Writes `lib/dn_release_version.g.dart` containing the exact bundle hash and release tag.
   - Registers the release artifact with the private registry (`dartpub.dev`).
2. **`dn patch [android|ios]`**:
   - Re-compiles the current Dart code and performs byte-level kernel diffing against the release baseline stored in `.dn_code_push/`.
   - Produces a minimal patch payload.
   - Publishes the patch payload to the OTA server. At runtime, the client app downloads and loads the patch safely before mounting root widgets.

## 5. `dn` CLI Command Reference

| Command | Description |
|---|---|
| `dn create <app_name>` | Scaffolds a new DartNative project with native iOS (SceneDelegate) and Android projects. |
| `dn run` | Builds and launches the app on a connected device/emulator with Hot Reload support. |
| `dn build [apk\|appbundle\|ios\|ipa]` | Compiles production binaries for Android or iOS. |
| `dn pub get` | Resolves pub dependencies and regenerates `dartnative_plugin_registrant.dart`. |
| `dn release [android\|ios]` | Compiles a production release and records Code Push baseline artifacts. |
| `dn patch [android\|ios]` | Generates and uploads an over-the-air code push patch for a release baseline. |
| `dn doctor` | Diagnoses local developer environment dependencies (CocoaPods, Android SDK, Xcode, PATH). |
| `dn clean` | Deletes build artifacts, build directories, and temporary kernel caches. |
